# Кандидатогенерация для поиска услуг Авито

Для каждого запроса из `benchmark_queries.parquet` решение отбирает до 50 объявлений из `benchmark_items.parquet`. Результат на платформе: **Recall@50 = 0.8756**.

## Структура

```
data/NLP_avito_interns-dataset/   ← сюда положить train.parquet, benchmark_queries.parquet, benchmark_items.parquet
src/
  common.py       загрузка данных, стемминг, кэш, валидационный сплит, метрика
  embed.py        эмбеддинги объявлений (multilingual-e5-small)
  retriever.py    пул по локациям, признаки, отбор ~600 кандидатов на запрос
  ranker.py       ранжирующая модель (HistGradientBoosting)
  build_val.py    кандидаты с разметкой на валидационном сплите (обучающие данные ранкера)
  cv_ranker.py    оценка Recall@50 на валидации
  make_answer.py  финальный прогон → answer.csv
cache/            создаётся автоматически
```

## Запуск

```bash
python3.12 -m venv .venv && .venv/bin/pip install -r requirements.txt

.venv/bin/python src/embed.py            # кэш + эмбеддинги объявлений (~20 мин)
.venv/bin/python src/build_val.py 0      # валидационные сплиты, по ~4 мин каждый
.venv/bin/python src/build_val.py 1
.venv/bin/python src/build_val.py 2
.venv/bin/python src/cv_ranker.py 0 1 2  # (опционально) Recall@50 на валидации
.venv/bin/python src/make_answer.py      # → answer.csv
```

Шаги запускать последовательно: пик памяти одного шага около 5 ГБ. Веса модели e5 скачиваются с HuggingFace при первом запуске, дальше всё работает локально, без внешних API.

Эмбеддинги я считал на GPU Mac (MPS). На CPU или другом GPU числа совпадают примерно до 1e-6, поэтому у пограничных позиций топ-50 возможны единичные расхождения с отправленным файлом.

## Подход

**Данные и признаки.** Из train используются пары «запрос → выбранное объявление». Для каждой пары «запрос — объявление» считаются:
- **Локация.** В 83% случаев объявление из той же локации, что и поиск. У 17% запросов в их локации объявлений нет вовсе (это регион). Поэтому по train строится матрица переходов «локация поиска → локация объявления», и из неё берутся пул кандидатов и признак вероятности.
- **Текст.** TF-IDF по основам слов (стеммер Snowball) для заголовка, параметров и описания, плюс TF-IDF по буквенным n-граммам заголовка против опечаток и словоформ.
- **Расширение запроса по train.** Находим похожие train-запросы (kNN) и сравниваем объявление с профилем объявлений, которые по ним выбирали. Так «автоподбор» связывается с «осмотром автомобиля». Из тех же соседей получается распределение подкатегорий (`microcat`).
- **Смысловое сходство.** Эмбеддинги `multilingual-e5-small`: косинус «запрос ↔ объявление» и тот же kNN-профиль в пространстве эмбеддингов.
- **Прочее.** Совпадение фильтров поиска с параметрами объявления, рейтинг, отзывы, цена.

ID-признаки объявлений не используются: 90% объявлений бенчмарка в train не встречаются.

**Модели.**
1. Предотбор ~600 кандидатов: топ по линейной смеси сигналов, объединённый с топами по каждому сильному сигналу отдельно.
2. `HistGradientBoostingClassifier` на ~70 признаках, включая ранг признака внутри запроса и отставание от лучшего кандидата. В ответ идут 50 лучших.

**Проверка качества.** Валидация построена из train так, чтобы повторять бенчмарк:
- по одному отложенному запросу на уникальный текст;
- 37% текстов встречаются в train, как и в бенчмарке;
- корпус 189k объявлений.

Всего 3 сплита по 2500 запросов, ранкер оценивается 2-fold CV по запросам. Все строки с правильными объявлениями валидации удалены из обучающей части, иначе модель запоминала их заголовки через похожие запросы, а на бенчмарке такого не будет.

| Версия | Валидация | Платформа |
|---|---|---|
| Линейная смесь сигналов | 0.703 | — |
| TF-IDF + kNN + ранкер | 0.889 | 0.8645 |
| + эмбеддинги e5 | 0.905 | **0.8756** |

**Найденные ошибки и что с ними сделано.**
- **Запросы из «региона», где объявлений нет (17%).** Помогла матрица переходов локаций вместо жёсткого совпадения. Потолок полноты пула 98%.
- **Разные слова для одного смысла** («скупка» ↔ «выкуп»). Помогли kNN-расширение по train-запросам и эмбеддинги.
- **Сильное объявление терялось в общей смеси сигналов.** Кандидаты добираются по каждому сигналу отдельно.
- **Утечка в валидации** через заголовки позитивов в train. Такие строки исключаются из обучающей части.
- **Оставшиеся потери.** ~5% правильных объявлений не попадают в кандидаты, ~5% попадают, но оказываются ниже 50-го места.
